# Lavender Storybook

Lavender Storybook is a design system foundation for finance applications including [Lavender Finance](https://lavender-finance.vercel.app/), covering design tokens, reusable components, responsive behavior, and accessibility.

## The three problems

The system addresses three main problems:

1. **Inconsistency:** Teams were making repeated decisions about spacing, color, typography, and component behavior, producing subtle differences across the product.
2. **Design-to-code drift:** Components could look correct in Figma while having different names, properties, states, or behavior in production.
3. **Incomplete system states:** Happy paths were usually designed, but responsive behavior, validation, loading, disabled states, dark mode, and accessibility requirements were easier to overlook.

## Why this matters for finance applications

Finance products handle dense, sensitive information and consequential actions, so consistency is not merely aesthetic—it improves comprehension, prevents errors, and builds user trust.

## How Its Organized

### Component Organization

Components are organized by product-facing category.

I considered organizing them using atomic design—atoms, molecules, and organisms—but chose categories because people usually search based on the problem they are solving: “I need a form control” or “I need a feedback component.”

Atomic design is useful for explaining composition, but financial apps have component categories like charts that don't always compose easily.

### Token organization

Tokens follow a layered architecture:

**Primitive tokens** store raw values, such as blue-600, space-16, or radius-8.

**Semantic tokens** describe purpose, such as text-primary, surface-raised, or space-page-gutter.
