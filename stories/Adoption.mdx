# Adoption and Impact

---

## What adopted it

| Surface | What it takes from the system |
| --- | --- |
| **Lavender Finance** | Tokens, Button, Badge, Chart, TransactionList, theme switch |
| **Lavender Portfolio** | Tokens, Dawn/Moon, shared action and surface language |
| **This Storybook** | Source of truth — 25 components, token pages, interaction tests |

One token file. A theme switch is `class="dark"` on the document root, not a per-component `if (theme)`.

---

## What changed

**Fewer implementations of the same control.** Save is Button variants, not three product-specific hexes and radii. Payment status is Badge (`success` / `warning` / `danger`), not a green that fails on Moon.

**Theme is a remap, not a rewrite.** Dawn and Moon assign different primitives to the same semantic names. Finance and the portfolio flip together.

**Accessibility is inherited.** Modal, Tabs, Accordion, Dropdown, and Tooltip ship with keyboard support. Contrast lives in tokens checked against WCAG AA, not in a one-off screen QA.

**Tests run where the UI lives.** `play` functions cover the stories in a real browser. Portal cases (Modal) assert on `document.body`. `addon-a11y` runs axe on every story.

**Extraction has a rule.** Two products → it comes back to this repo. That is the federated loop: Finance finds the need, the component lands here, Portfolio gets it without a rewrite.

---

## What to look at

Switch **Lavender Dawn / Lavender Moon** in the toolbar, then open **Data Display / TransactionList** and **Layout / Modal**. The theme change should not require a component edit. That is adoption working.
